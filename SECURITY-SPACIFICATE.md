# Security-Spacificate — архитектура второго этапа

> **Статус:** проектная ветка. В этом документе описана новая многопанельная система мониторинга для Ryazha-Status-Monitor. Стабильный релиз `v1.5.0`, ветка `main` и опубликованные assets не изменяются.

## Назначение

Security-Spacificate — это не ещё один компактный режим поверх существующих. Это отдельный **многосистемный экран диагностики**, который выводит одновременно несколько независимых групп телеметрии. На экране будут стоять две крупные области: левая и правая; каждая получает собственный набор карточек, собственную частоту обновления и собственный приоритет. В результате пользователь видит не одну длинную сводку, а цельную «мега-систему»: состояние игры, производительности и питания читаются параллельно.

Название ветки отражает изолированный экспериментальный статус. Однако сама ветка находится в публичном репозитории, поэтому она **не является хранилищем секретных данных**. Любые ключи, закрытый исходный код, личные данные или невыпущенные файлы должны оставаться вне этой ветки и публичного GitHub-репозитория.

| Цель | Решение |
| --- | --- |
| Одновременно видеть несколько систем | Две независимые панели: `Левая` и `Правая`, каждая с собственным набором карточек. |
| Не ломать Mini, Full, FPS+Гц и другие готовые режимы | Новый режим и новые внутренние слои создаются отдельно; существующие режимы остаются на текущем пути рендеринга. |
| Не превращать экран в перегруженную таблицу | Карточки имеют фиксированные роли, короткие русские подписи и приоритеты отображения. |
| Поддержать будущие тяжёлые расширения | Данные, компоновка, отрисовка, касания и конфигурация разделены на самостоятельные модули. |
| Сохранить стиль Ряженки | Палитра Ryazha-clk, золотые рамки, белый текст, красно-розовые акценты и уважение к пользовательским настройкам цветов. |

## Целевой экран

Базовый экран называется **«Security-Spacificate»**. Он рассчитан на ландшафтные разрешения Switch и состоит из центрального зазора и двух колонок. Каждая колонка может быть скрыта, закреплена либо переключена на другой профиль без перезапуска overlay.

| Область | Основное содержимое | Дополнительное содержимое | Приоритет |
| --- | --- | --- | --- |
| **Левая панель: игра и производительность** | FPS игры, фактическая частота экрана, время кадра | загрузка ЦПУ и ГПУ, температура, профиль EMA | Высокий при запущенной игре |
| **Правая панель: система и питание** | ОЗУ, заряд, напряжение, ток, мощность | вентилятор, док-статус, Wi-Fi, время работы | Высокий при зарядке и диагностике |
| **Нижняя строка состояния** | текущий профиль, активные фильтры, режим касания | предупреждение и метка устаревших данных | Всегда видима, но минимальна |

Карточки не будут жёстко завязаны на одну колонку. В конфигурации профиль определит, какие карточки входят в `left`, `right` и `footer`, а безопасный порядок по умолчанию обеспечит читаемость без первоначальной настройки. Это даст возможность позже добавить третий профиль «Тепло и питание» или «Тест игры», не копируя отрисовку.

## Внутренняя архитектура

Новая система разделяется на пять слоёв. Главный принцип: поток получения данных никогда не рисует интерфейс, а интерфейс никогда не опрашивает железо напрямую. Рендер получает только готовый атомарный снимок состояния. Это устраняет разнобой значений между карточками и не позволяет тяжёлому сенсору тормозить кадр UI.

```text
Сенсоры и сервисы Switch
          │
          ▼
  Telemetry Collectors ──► Normalizer + EMA ──► Telemetry Snapshot Bus
                                                       │
                 ┌─────────────────────────────────────┴─────────────────────────────────────┐
                 ▼                                                                           ▼
        Security Layout Engine                                                      Existing mode renderers
                 │
                 ▼
       Left / Right / Footer card trees
                 │
                 ▼
      Ryazhahand rendering and direct HID gestures
```

| Слой | Ответственность | Запрещённые зависимости |
| --- | --- | --- |
| **Telemetry Collectors** | Считывают FPS, герцы, нагрузки, температуры, питание, память, сеть и игровой контекст. | Никакого UI и записи конфигурации. |
| **Normalizer + EMA** | Приводит единицы измерения, ограничивает невозможные значения, ведёт раздельные EMA-фильтры и метки свежести. | Никаких вызовов рендеринга. |
| **Telemetry Snapshot Bus** | Публикует единый неизменяемый снимок для кадра интерфейса. | Никаких обращений к физическому сенсору. |
| **Security Layout Engine** | Выбирает карточки, размеры, колонки, развёрнутые состояния и fallback на малом экране. | Никакого прямого чтения железа. |
| **Input Controller** | Разрешает перетаскивание всего экрана, щипок масштаба и касание конкретной карточки без конфликтов. | Никаких изменений данных мониторинга. |

## Модель данных

Каждый элемент будет иметь значение, единицу, время последнего достоверного чтения и признак доступности. Нулевое значение и недоступный сенсор не должны выглядеть одинаково: вместо ложного `0` карточка покажет русское состояние **«Нет данных»**. При недавнем устаревании значение остаётся на экране, но помечается спокойным красно-розовым индикатором.

| Группа | Примеры полей | Обновление | Фильтрация |
| --- | --- | ---: | --- |
| Производительность | FPS, время кадра, герцы дисплея | Частое | EMA FPS отдельно от герц |
| Вычисления | ЦПУ, ГПУ, ОЗУ | Среднее | EMA загрузки отдельно |
| Температуры | ЦПУ, ГПУ, плата, батарея | Среднее | EMA температур отдельно |
| Питание | заряд, ток, напряжение, мощность, статус зарядки | Среднее | EMA питания отдельно |
| Контекст | игра, разрешение, док, сеть, профиль | По событию или редко | Без сглаживания |

## Компоновка и касания

В новой системе жесты не должны мешать просмотру. В первой версии ввод будет иметь три ясные зоны: свободное место вокруг карточек перемещает весь виджет, касание двумя пальцами в свободной зоне меняет общий масштаб, а нажатие одной карточки переключает только её компактный или расширенный вид. Карточки не начнут самопроизвольно двигаться при простом чтении значения.

| Жест | Действие | Границы |
| --- | --- | --- |
| Перетаскивание одним пальцем по свободной зоне | Перемещает весь Security-Spacificate | Работает мгновенно; задержка касания — `0`. |
| Щипок двумя пальцами | Масштабирует всю двухпанельную систему | Диапазон `70–150%`; геометрия и обводки пересчитываются полностью. |
| Нажатие карточки | Раскрывает вторичные строки только этой карточки | Не меняет глобальное положение. |
| `+` | Открывает настройки Security-Spacificate | Сохраняет текущий выбранный профиль. |
| `B` | Закрывает меню без отмены ранее сохранённых параметров | Не откатывает уже применённые изменения. |

## Изменения в libryazhahand

Изменения библиотеки нужны, но их нельзя смешивать с логикой мониторинга. Сначала в отдельной экспериментальной ветке libryazhahand появятся только **универсальные** примитивы, пригодные и другим overlay: масштабируемый контейнер карточек, двухколоночный layout, измерение безопасной зоны касаний и маршрутизация щипка. Метрики FPS, температуры и питания останутся внутри Ryazha-Status-Monitor.

| Компонент библиотеки | Назначение | Граница ответственности |
| --- | --- | --- |
| `SplitPanel` | Раскладка левой и правой области с центральным зазором. | Знает размеры и фокус, но не знает телеметрию. |
| `CardGrid` | Высота, интервалы, обводки, переполнение текста и масштаб. | Рисует карточки, но не считывает данные. |
| `GestureRouter` | Приоритет перетаскивания, щипка и нажатия. | Передаёт жест, но не меняет конфиг самовольно. |
| `SnapshotText` | Единый вывод значения, единицы и состояния «Нет данных». | Не решает, как получать значение. |

## Конфигурация и обратная совместимость

Параметры будут жить в отдельной секции `[security-spacificate]`, не смешиваясь с `[full]`, `[mini]`, `[fps-counter]` и другими готовыми режимами. Версия схемы конфигурации даст возможность обновлять значения по умолчанию, не ломая пользовательскую палитру или расположение.

```ini
[security-spacificate]
schema_version = 1
enabled = false
profile = dual-performance-power
position_x = 0
position_y = 0
touch_scale = 100
left_cards = fps_hz,cpu_gpu,frame_time
right_cards = ram,power,thermal
footer_cards = game,network
```

По умолчанию режим останется **выключенным**. Это важно: экспериментальная мега-система не должна включаться у пользователей автоматически и не должна менять знакомый «Полный» режим.

## Этапы внедрения

| Этап | Результат | Изменяет библиотеку | Изменяет готовые режимы |
| --- | --- | --- | --- |
| **0. Проектирование** | Эта ветка, схема данных, макет конфигурации и критерии совместимости. | Нет. | Нет. |
| **1. Snapshot Core** | Общий снимок телеметрии и раздельные состояния доступности. | Нет. | Нет. |
| **2. Карточки и две панели** | Нерегистрируемый экспериментальный режим с тестовыми данными текущих сенсоров. | Возможно, только layout-примитивы. | Нет. |
| **3. Жесты и профили** | Щипок всей системы, перетаскивание, компактное/развёрнутое состояние и сохранение. | Да, только общие виджеты. | Нет. |
| **4. Стабилизация** | Нагрузочные проверки, проверка на handheld/docked/1080p, перевод всех строк. | При необходимости. | Нет. |
| **5. Решение о выпуске** | Отдельное решение: оставить экспериментом, сделать preview или переносить в main. | Только после тестов. | Только после явного решения. |

## Критерии готовности

Перед любым preview должны быть выполнены следующие условия: существующие режимы сохраняют своё поведение, все строки интерфейса русские, недоступные метрики не показывают ложные нули, цвета берутся из пользовательских настроек, границы не исчезают на максимальном масштабе, а касания проверены отдельно в handheld, docked и 1080p. Никакой новый тег и никакая перезапись релиза `v1.5.0` из этой ветки не выполняются без отдельного решения владельца.
