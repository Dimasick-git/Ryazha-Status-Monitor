# Security

> **English — short:** Ryazha Status Monitor treats SMD modes and SMSE extensions on the SD card as untrusted input. Version 1.4.8+ enforces size, buffer, parser, path, and formatting limits; CI dependencies are pinned to immutable revisions. Install modes and extensions only from sources you trust.

# Безопасность Ryazha Status Monitor

## Модель доверия

Проект работает в среде Atmosphère CFW и читает режимы `.smd`, расширения `.smse`, тему и конфигурацию с SD-карты. Эти файлы считаются **недоверенным входом**: ошибки в них не должны приводить к произвольному выделению памяти, выходу за границы буфера, загрузке файлов за пределами каталога режимов или нестабильной работе оверлея.

> SMSE-расширения предназначены для запросов к системным сервисам Switch. Они не являются песочницей: устанавливайте только расширения, которым вы доверяете, и не копируйте файлы `.smse` из неизвестных сборок.

## Защиты, реализованные после аудита

| Поверхность | Защита |
| --- | --- |
| SMD-файлы | Размер ограничен **512 КиБ** при загрузке с диска и из памяти; проверяются ошибки позиционирования и неполного чтения. |
| Аргумент `--file` | Принимаются только относительные имена `.smd` длиной до 128 символов внутри `config/status-monitor/modes`; отклоняются абсолютные пути, пустые сегменты, `.` и `..`. |
| SMD-форматирование | Ширина/точность одного поля ограничена **4096**, общий результат — **1 МиБ**. Большое поле получает безопасный маркер вместо динамического выделения или чтения за пределами буфера. |
| SMSE-файлы | Размер одного файла — до **256 КиБ**, буфер команды — от 1 до **65536** байт, каталог — до **64** файлов. |
| SMSE-структуры | Не более **128** команд в файле и **128** полей в структуре; каждое поле проверяется на принадлежность буферу до выделения памяти и привязки указателя. |
| SMSE-парсер | Числа принимаются только при полном разборе без лишних символов; проверяются переполнение `u32`, имя сервиса (1–8 допустимых ASCII-символов), полный файл и длина регулярного выражения (до **512** байт). |
| CI и контейнер | GitHub Actions закреплены по SHA; стандартные задачи имеют только `contents: read`; job публикации получает `contents: write`. Образ devkitPro закреплён по digest вместо `latest`. |

## Результаты проверки

Ручной аудит охватил SMD-парсер, загрузчик SMSE, аргументы запуска, сценарии сборки, CI, Dockerfile и UI-подсказки. Дополнительно выполнены строгая host-сборка, AddressSanitizer/UndefinedBehaviorSanitizer, регрессии встроенных SMD-режимов, локальная проверка SMSE и статический анализ C++.

Статический анализ не оставил подтверждённых предупреждений о чтении/записи за границами буфера, утечках, нулевых указателях или неопределённом поведении в проверяемом коде. Косметические сообщения стороннего анализатора для C/libnx-заголовков и vendored-кода не считаются доказанными дефектами проекта и не скрывают результат строгой сборки.

## Использование современных глифов кнопок

Подсказки комбинаций синхронизированы с картой **Switch 2 Style** из `libryazhahand`: используются корректные современные глифы `Plus`, `Minus`, `LS`, `RS`, `SL` и `SR`. Порядок кнопок теперь фиксирован, поэтому один и тот же битовый набор всегда сохраняется и отображается одинаково.

## Остаточные риски и рекомендации

| Риск | Что делать |
| --- | --- |
| Недоверенное SMSE-расширение | Не устанавливайте его. Расширение получает возможность выполнять описанные им IPC-запросы в пределах прав оверлея. |
| Вредоносные файлы на SD-карте | Используйте проверенные источники, не запускайте режимы из случайных архивов и регулярно проверяйте содержимое `config/status-monitor/`. |
| Уязвимости сторонних библиотек | Следите за обновлениями `libtesla`, libnx, devkitPro и GitHub Actions; SHA-pin защищает от незаметной подмены тега, но не заменяет обновление при обнаружении CVE. |
| CFW-среда | Не смешивайте непроверенные sysmodule и патчи. Безопасность оверлея зависит от всей установленной цепочки CFW. |

## Сообщение о проблеме

Не публикуйте эксплойт, приватные данные или рабочий вредоносный `.smd`/`.smse` в открытой задаче. Создайте private security advisory в репозитории либо сначала удалите конфиденциальные данные и приложите минимальный безопасный пример воспроизведения.
